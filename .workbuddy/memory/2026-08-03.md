# 2026-08-03

## 排查并修复：切换壁纸后 Windows 桌面背景不改变

**症状**：壁纸功能（动态壁纸引擎）开发完成后，切换壁纸桌面无任何变化。

**根因**（`src/Wallpaper/DesktopWallpaperHost.cs`，两个叠加 bug）：
1. **Win11 24H2 挂载目标错误**：`EnsureBackgroundHost()` 优先返回 Progman 下生成的 WorkerW 子窗口。实测（探针 + 截图像素分析，普通权限和管理员权限结果一致）挂到该 WorkerW 下的窗口完全不可见。24H2 上正确宿主是 **Progman 本身**（子窗口落在图标层 SHELLDLL_DefView 之下、静态壁纸之上，实测 ~40 万像素可见 vs 其他方案 <3000）。
2. **缺少 WS_CHILD 样式**：原代码只改扩展样式后直接 `SetParent`。MSDN 明确 SetParent 不改变 WS_CHILD/WS_POPUP；实测不改样式时 `GetParent=0`、`IsChildOfHost=False`，父子关系未建立，渲染窗口"消失"，桌面永远不变。

**修复**（已提交到工作区，未 commit）：
- `EnsureBackgroundHost()`：先找 24H2 之前的顶层 WorkerW 兄弟窗口（且需可见）；找不到则返回 Progman（24H2 路径）。
- `Attach()`：SetParent 前设置 `WS_CHILD`、清除 `WS_POPUP`；SetParent 失败返回 false；挂到 Progman 时用 `SetWindowPos(…, defView, …)` 把渲染窗口压在图标视图正下方，保证桌面图标在最上层。

**验证**：构建 0 错误；219 个单元测试全通过；探针实证修复路径（Q2 方案）在普通/管理员权限下均可见。注：UIPI 不阻止高完整性进程 SetParent 到中完整性 Explorer 窗口，requireAdministrator 不是本问题的原因。

**环境备注**：用户机器 Win11 24H2、双 2560×1440 @150% DPI（副屏在右侧 y=-3）、sudo 已禁用。
